# 🤖 ربات فضول‌یاب — نسخه Railway

ربات بله (Bale) با سیستم فضول‌یابی، VIP، پرداخت، XP و سطح‌بندی — آمادهٔ دیپلوی روی Railway.

---

## 📦 ساختار پروژه

| فایل | توضیح |
|---|---|
| `main.py` | کد اصلی ربات (پایگاه داده، هندلرها، پخش همگانی، بکاپ شبانه) |
| `config.py` | تنظیمات — **همه‌چیز از متغیرهای محیطی** خوانده می‌شود (هیچ مقدار حساسی هاردکد نیست) |
| `texts.py` | متن‌های پیام‌ها |
| `tasks.py` | تسک‌های پس‌زمینه (بکاپ شبانه، انقضای VIP و...) |
| `Dockerfile` | ایمیج پایتون ۳.۱۱ + نصب وابستگی‌ها |
| `railway.toml` | تنظیمات دیپلوی Railway (builder=DOCKERFILE، restart on failure) |
| `requirements.txt` | pyTelegramBotAPI، requests، jdatetime |

---

## 🧰 پیش‌نیازها (قبل از شروع)

1. **اکانت Railway:** در [railway.com](https://railway.com) ثبت‌نام کنید. توجه: برای دیپلوی باید Trial فعال باشد یا پلن Hobby (با کارت بانکی بین‌المللی) فعال شود — بدون آن Deploy انجام نمی‌شود.
2. **توکن ربات از بله:**
   - در بله به [@BotFather](https://t.me/BotFather) پیام بدهید (ربات رسمی ساخت ربات)
   - `/newbot` ← اسم و یوزرنیم بدهید ← توکن مثل `123456:AAH...` تحویل می‌گیرید
3. **ADMIN_ID (شناسه عددی خودتان):**
   - راه ساده: به یکی از ربات‌های «نمایش شناسه» داخل بله پیام دهید و عدد خودتان را بردارید، **یا**
   - بعد از اولین اجرای ربات، هر پیامی که هر کاربری به ربات بدهد در لاگ‌ها `user_id` دارد

## 🚀 دیپلوی روی Railway (گام‌به‌گام)

اول فایل ZIP را در یک پوشه Extract کنید. سپس **یکی از دو مسیر** زیر را انتخاب کنید:

### مسیر الف — با GitHub (برای آپدیت‌های بعدی راحت‌تر)
1. یک ریپوی **Private** در GitHub بسازید و محتوای ZIP را push کنید
2. وارد [railway.com](https://railway.com) شوید → **New Project** → **Empty Project**
3. **Add a Service → GitHub Repo** → همین ریپو را انتخاب کنید
4. Railway خودش `Dockerfile` را تشخیص می‌دهد و Build می‌کند
5. از این به بعد با هر `git push` جدید، دیپلوی خودکار انجام می‌شود

### مسیر ب — مستقیم از کامپیوتر، بدون GitHub (دقیقاً همان کاری که در این پروژه شد)
```bash
# 1) نصب Railway CLI
#    ویندوز (PowerShell):
powershell -c "iwr https://railway.app/install.ps1 -useb | iex"
#    مک/لینوکس (ترمینال):
curl -fsSL https://railway.app/install.sh | sh

# 2) لاگین (مرورگر باز می‌شود)
railway login

# 3) داخل پوشه‌ی کد:
cd fozol_railway
railway init          # پروژه بسازید (اسم مثلاً fozol-bot)
railway up            # آپلود و دیپلوی
```

### گام ۲ — ساخت Volume (مهم! دیتابیس بدون این با هر دیپلوی پاک می‌شود)
1. در داشبورد Railway روی سرویس کلیک کنید → تب **Settings** (یا روی سرویس راست‌کلیک) → **Attach Volume**
2. Mount Path را دقیقاً `/data` بگذارید
   - با CLI: `railway volume add --mount-path /data`

### گام ۳ — تنظیم Variables
در تب **Variables** این مقادیر را بسازید:

| متغیر | ضروری؟ | مقدار | توضیح |
|---|---|---|---|
| `BOT_TOKEN` | ✅ | توکن ربات بله (از BotFather بله) | بدون آن ربات اجرا نمی‌شود |
| `ADMIN_ID` | ✅ | شناسه عددی سوپر ادمین | مثال: `133609405` |
| `PROVIDER_TOKEN` | ➖ | توکن درگاه پرداخت (`WALLET-...`) | خالی = دکمه‌های خرید غیرفعال |
| `DB_PATH` | ✅ | `/data/bot_data.db` | مسیر دیتابیس روی Volume |

**Variables اختیاری (عکس/ویدیوی منوها):** از نسخهٔ فعلی، هر ۹ file_id عکس/ویدیو به‌صورت **هاردکد در config.py** قرار دارند (مقادیر عمومی هستند) و منوها بدون هیچ تنظیمی با تصویر نمایش داده می‌شوند. اگر خواستید یکی را عوض کنید، دو راه دارید:
- مقدار جدید را مستقیم در `config.py` ویرایش و redeploy کنید، یا
- متغیر محیطی همنام (مثل `LEADERBOARD_PHOTO_ID`) در Variables بسازید — مقدار Variable همیشه بر هاردکد اولویت دارد.

> 💡 file_id جدید چطور بگیرید؟ فایل موردنظر را در بله برای ربات بفرستید؛ `file_id` آن در پاسخ/لاگ API هست. فرمت: `ownerId:mediaId:part:hash`

### گام ۴ — Deploy
- با ذخیرهٔ هر Variable دیپلوی خودکار انجام می‌شود
- یا دستی: تب **Deployments** → **Deploy**
- CLI: `railway up`

### گام ۵ — تأیید سلامت
لاگ سالم باید این شکلی باشد:
```
Mounting volume on: ...
Starting Container
🚀 ربات @yourbot راه‌اندازی شد.
✅ ربات @yourbot | ادمین: ... | پرداخت: فعال/غیرفعال | عضویت اجباری: ...
```
سپس در بله به ربات `/start` بدهید.

## 🔄 بازیابی دیتابیس قبلی (/restore)

1. فایل `bot_data.db` قدیمی را داشته باشید
2. در چت ربات دستور `/restore` را بزنید
3. فایل دیتابیس را به‌عنوان document بفرستید
4. ربات جایگزین می‌کند و ری‌استارت منطقی می‌شود

> ⚠️ اگر تعداد کاربران دیتابیس خیلی کم باشد، ربات خودش از ادمین بکاپ درخواست می‌کند.

## 🌙 بکاپ خودکار شبانه
هر شب ساعت **۰۰:۰۰ به وقت ایران**، اسنپ‌شات کامل دیتابیس به‌صورت فایل به پی‌وی سوپر ادمین (`ADMIN_ID`) ارسال می‌شود. (`nightly_backup_loop` در main.py)

## 🌐 دو حالت دریافت آپدیت‌ها
- **Polling (پیش‌فرض):** اگر `WEBHOOK_URL` ست نباشد — مناسب شروع سریع
- **Webhook:** متغیرهای زیر را ست کنید تا ربات وب‌سرور روی `$PORT` بالا بیاورد:
  - `WEBHOOK_URL` = آدرس عمومی https
  - `WEBHOOK_SECRET` = اختیاری؛ برای اعتبارسنجی هدر secret

## 🔧 عیب‌یابی (Troubleshooting)

| مشکل | علت / راه‌حل |
|---|---|
| `❌ توکن یا شناسه ادمین نامعتبر` + توقف | `BOT_TOKEN` یا `ADMIN_ID` در Variables ست نشده — پر کنید |
| `Polling error: argument of type 'Update' is not iterable` | **رفع شده** در نسخهٔ فعلی (خط حلقهٔ polling — استفاده از `getattr(upd, "update_id")`) |
| خطای 404 در دانلود فایل حین /restore | قبلاً به‌خاطر `api.telegram.org` بود — الان `FILE_URL` به بله اشاره می‌کند (رفع شده) |
| عکس منوها نمایش داده نمی‌شود | file_id مربوطه در Variables ست نشده؛ یا نام کاربری دارای `_`/`*` بود که `escape_md` حالا مدیریت می‌کند |
| ربات بعد از deploy دیتاها را فراموش کرد | Volume attach نشده یا `DB_PATH` اشتباه است — باید `/data/bot_data.db` باشد |
| `Unauthorized` در CLI ریلوی | توکن Account فقط با هدر Authorization کار می‌کند؛ برای CLI بهتر است Project Token بسازید (Settings → Tokens) |
| کرش‌لوپ بعد از تغییر کد | لاگ Deployments را ببینید؛ `restartPolicyType=ON_FAILURE` تا ۵ بار ری‌استارت می‌کند |

## 🔐 امنیت — چک‌لیست

- [ ] هیچ توکنی در کد نیست — همه در Variables
- [ ] ریپو خصوصی (private) نگه دارید
- [ ] بعد از اتمام کار، توکن‌های موقت Railway را از [Account Settings → Tokens](https://railway.com/account) **revoke** کنید
- [ ] Project Token های بلااستفاده را حذف کنید (Project → Settings → Tokens)
- [ ] توکن ربات را اگر لو رفت، از BotFather بله reset کنید
